用 Nginx 自建 Gemini API 反向代理网关

AI #Gemini API #Nginx #反向代理 #API网关

折腾 Gemini API 的时候，很多人图省事会拿免费 Serverless 平台（像 Cloudflare Workers 或 Deno Deploy）套一层转发，但公共免费平台的条款和配额随时都在变，稍微多调几次就容易撞限流甚至被停。

不如直接在自己手头的 Linux 服务器上用 Nginx 配个标准反向代理网关：SSL 证书自己管、日志自己看、规则自己改，稳得多。之前翻到社区里一篇用 Nginx 转发 Gemini 接口的思路，自己实测跑通之后，顺手写了个一键配置脚本 GeminiProxy，省得每次换机器都要手搓配置。

需要准备的东西¶

  • 一台能正常连上目标 API 端点的 Linux 云服务器（1C1G 或 2C2G 就绰绰有余）
  • 一个有效的 Gemini API Key
  • 一个解析到这台服务器的域名，以及对应的 SSL 证书（.pem 和 .key）

一、装好系统并连上 SSH¶

机器到手先装个干净的 Debian 或 Ubuntu LTS（重装前记得备份原数据），然后直接 SSH 登上去：

ssh root@your_server_ip

二、跑配置脚本¶

拉一下仓库里的脚本运行就行：

wget https://raw.githubusercontent.com/Cnfte/geminiproxy/refs/heads/main/proxy.sh && sudo bash proxy.sh

脚本会自动检查并装好 Nginx，接着弹出来一个交互菜单。

三、填域名、端口和证书¶

在菜单里选 1 开始配置：

  1. 输入域名：填你准备好的域名（比如 api.yourdomain.com），提前在 DNS 面板把 A 记录指到这台机器的 IP。
  2. 端口设置：正常机器直接用 80 / 443 就行；如果是 NAT 机器做了端口映射（比如 HTTPS 映射到 40443），记得在服务商安全组和系统防火墙里把对应端口放行，访问地址写成 https://api.yourdomain.com:40443。
  3. SSL 证书：用 Let's Encrypt 或者其他免费证书平台签一份，把 .pem 证书文件和 .key 私钥文件的绝对路径填进去。

填完回车，脚本会自动把 Nginx 站点配置写好并重载。

四、接客户端测试¶

配置生效后，把你的网关域名和 API Key 填进 Chatbox、NextChat 这类支持自定义 Base URL 的客户端里，发一条消息测通就算完事。

最后补一句：这套脚本就是标准的 Nginx 反向代理和 HTTPS 网关配置，自己开发调试用挺方便，使用过程中注意遵守当地法规和各家平台的服务条款。

When messing around with the Gemini API, many people will use a free serverless platform (such as Cloudflare Workers or Deno Deploy) to save trouble. However, the terms and quotas of public free platforms change at any time. If you adjust it a few times, it is easy to hit the traffic limit or even be stopped.

It is better to directly use Nginx on your own Linux server to configure a standard reverse proxy gateway: manage the SSL certificate yourself, read the logs yourself, and change the rules yourself, which is much more stable. I came across an article in the community about using Nginx to forward the Gemini interface. After running the test myself, I wrote a one-click configuration script. GeminiProxy, saving you the trouble of manually configuring it every time you change machines.

Things to prepare¶

  • A Linux cloud server that can normally connect to the target API endpoint (1C1G or 2C2G is more than enough)
  • A valid Gemini API Key
  • A domain name that resolves to this server, and the corresponding SSL certificate (.pem and .key）

1. Install the system and connect to SSH¶

When you get the machine, first install a clean Debian or Ubuntu LTS (remember to back up the original data before reinstalling), and then log in directly via SSH:

ssh root@your_server_ip

2. Run the configuration script¶

Just pull the script in the warehouse and run it:

wget https://raw.githubusercontent.com/Cnfte/geminiproxy/refs/heads/main/proxy.sh && sudo bash proxy.sh

The script will automatically check and install Nginx, and then an interactive menu will pop up.

3. Fill in the domain name, port and certificate¶

Choose in the menu 1 Start configuration:

  1. Enter domain name: Fill in the domain name you prepared (for example api.yourdomain.com), point the A record to the IP of this machine in the DNS panel in advance.
  2. Port settings: Used directly on normal machines 80 / 443 Just fine; if the NAT machine has done port mapping (for example, HTTPS is mapped to 40443), remember to release the corresponding port in the service provider security group and system firewall, and write the access address as https://api.yourdomain.com:40443。
  3. SSL certificate: Use Let's Encrypt or other free certificate platforms to sign a copy and put .pem certificate file and .key Fill in the absolute path to the private key file.

After filling in and pressing Enter, the script will automatically write the Nginx site configuration and reload it.

4. Connect to client test¶

After the configuration takes effect, fill in your gateway domain name and API Key into clients such as Chatbox and NextChat that support custom Base URLs, send a message to test, and you're done.

One last thing to add: This set of scripts is the standard Nginx reverse proxy and HTTPS gateway configuration. It is very convenient to develop and debug by yourself. During use, pay attention to comply with local regulations and the terms of service of each platform.
